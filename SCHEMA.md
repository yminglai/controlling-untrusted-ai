# Data contracts for `site/data/`

All files are UTF-8 JSON, generated by `pipeline/build_data.py` (taxonomy, papers, grey,
summaries_zh, stats, stream_recent) or by `pipeline/collect_news.py` / the seed sweep (stream,
stream_recent, the `stream_*` fields of stats). The front-end reads only these files. Field names
below are final; add fields only by extending this document.

Extended 2026-10-17 (review fixes): `taxonomy.json` subsection `counts.zh`; `grey.json` `also` and
`has_zh`, `confidence` closed set, `url` fallbacks; `stats.json` `source_generated`, `zh` and the
`stream_*` counts; `stream.json` `taxonomy_generated`; the new `stream_recent.json`.

## `taxonomy.json`

```json
{
  "title": "Controlling Untrusted AI: A Survey",
  "thesis": "<one paragraph from outline.json>",
  "readers": ["...", "...", "..."],
  "generated": "2026-10-17",
  "requirements": [
    {"id": "correct", "label": "Correct"}, {"id": "compliant", "label": "Compliant"},
    {"id": "in-scope", "label": "In scope"}, {"id": "within-budget", "label": "Within budget"},
    {"id": "safe", "label": "Safe"}
  ],
  "failure_sources": [
    {"id": "mistakes", "label": "Mistakes", "color": "#D95358", "blurb": "..."},
    {"id": "manipulation", "label": "Manipulation", "color": "#E09A3B", "blurb": "..."},
    {"id": "misalignment", "label": "Misalignment", "color": "#A37CAD", "blurb": "..."}
  ],
  "operations": [
    {"id": "failures", "label": "How Agents Fail", "section": "s2", "color": "#D95358", "lever": null},
    {"id": "constrain", "label": "Constrain", "section": "s4", "color": "#E27553", "lever": "deployment"},
    {"id": "observe", "label": "Observe", "section": "s5", "color": "#598DD2", "lever": "deployment"},
    {"id": "intervene", "label": "Intervene", "section": "s6", "color": "#E09A3B", "lever": "deployment"},
    {"id": "steer", "label": "Steer", "section": "s7", "color": "#65C2B9", "lever": "model"},
    {"id": "train", "label": "Train", "section": "s8", "color": "#8D86E8", "lever": "model"},
    {"id": "verify", "label": "Verify", "section": "s9", "color": "#62A16E", "lever": "verify"},
    {"id": "deploy", "label": "Deploy and Assure", "section": "s10", "color": "#A37CAD", "lever": "assurance"}
  ],
  "sections": [
    {
      "id": "s4", "number": 4, "title": "Constraining Agent Actions", "slug": "constrain",
      "operation": "constrain", "color": "#E27553", "purpose": "<from outline.json>",
      "subsections": [
        {
          "id": "s4_1", "number": "4.1", "title": "Least Privilege", "slug": "least-privilege",
          "bullets": ["<plan bullets from outline.json, LaTeX stripped>"],
          "counts": {"primary": 23, "selected": 3, "cross": 11, "grey": 1, "zh": 4}
        }
      ]
    }
  ]

```

Sections 1, 3 and 11 have `operation: null` and `color: "#7D7D7D"`. `counts.primary` = papers whose
`primary` is this subsection; `selected` = of those, cited in the PDF; `cross` = papers and reports
that list this subsection in `also`; `grey` = grey items whose `primary` is this subsection; `zh` =
papers and reports with `primary` here that carry a Chinese note (`has_zh`). A subsection may have
zero primary papers (2.3 Insider Threats in the October 2026 outline); the front-end renders the
head with an empty state.

## `papers.json`  (array, one object per arXiv paper; 1,788 items)

```json
{
  "key": "cao2026beyond",
  "arxiv_id": "2603.03116",
  "url": "https://arxiv.org/abs/2603.03116",
  "title": "Beyond Task Completion: ...",
  "authors": ["Hongliu Cao", "Ilias Driouich", "Eoin Thomas"],
  "year": 2026,
  "primary": "s1_1",
  "section": "s1",
  "score": 3,
  "selected": false,
  "label": "Procedure-Aware Evaluation",
  "one_line": "Procedure-aware evaluation on tau-bench shows ...",
  "reason": "27-78% of reported successes conceal policy violations",
  "also": [{"sid": "s2_1", "score": 3}],
  "reading_rank": 5,
  "has_zh": false
}
```

`label` = `labels_method_style.json[key]` else `short_label` else text before the first colon of the
title. `one_line` may be empty. `authors` is the full list (the UI truncates). `year` is an integer.
Sort order in the file: by `primary` (section order), then `selected` desc, `score` desc,
`reading_rank` asc (nulls last), `year` desc, `title`.

## `grey.json`  (array; union of `corpus_full.grey` and `grey_v2.entries`, deduplicated by URL/title)

```json
{
  "key": "greenblatt2025controlmeasures",
  "title": "An overview of control measures",
  "authors": ["Ryan Greenblatt"],
  "year": 2025,
  "venue": "AI Alignment Forum / LessWrong (Redwood Research)",
  "url": "https://www.alignmentforum.org/posts/...",
  "primary": "s7_2",
  "section": "s7",
  "label": "Redwood: Control Measures",
  "one_line": "Catalogue of core and long-tail control measures ...",
  "confidence": "verified",
  "selected": true,
  "also": [{"sid": "s10_3", "score": null}],
  "has_zh": true
}
```

`selected` = true when the item is in `corpus_full.grey` (cited in the PDF). `confidence` is one of
`verified | likely | unverified` (the source note "existing bib entry" maps to `verified`; the front-end
badges only `likely` and `unverified`). `url` is never empty: bib entries without a URL take the DOI or
publisher page from `GREY_URL_FALLBACK` in `build_data.py`. One record per document: when two bib keys
share a URL the first key is kept and the second key's subsection becomes an `also` entry with
`score: null`; `also` is otherwise `[]`. A grey item that is the same work as an arXiv paper (same bib
key, or its `arxiv_id` is in `papers.json`) is not emitted: the paper is marked `selected` and the
grey subsection is added to the paper's `also`. `has_zh` mirrors `papers.json`.

## `summaries_zh.json`  (object keyed by bib key; one entry per card that carries a note; loaded on demand)

```json
{
  "sharkey2025open": {
    "positioning": "...", "problem": "...", "method": "...", "findings": ["...", "..."],
    "deployer_takeaway": "...", "limitations": "...", "relation_to_subsection": "...",
    "reading_depth": "部分", "terms": ["mechanistic interpretability = 机制可解释性"], "doubts": "...",
    "sid": "s1_3", "text_depth": "partial"
  }
}
```

Field mapping from the source: 定位→positioning, 问题→problem, 方法→method, 发现→findings,
部署启示→deployer_takeaway, 局限→limitations, 与小节关系→relation_to_subsection, 阅读深度→reading_depth,
术语→terms, 存疑→doubts. Values stay in Chinese.

## `stats.json`

```json
{
  "generated": "2026-10-17",
  "source_generated": "2026-10-16",
  "papers": 1788, "grey": 164, "cited": 239, "zh": 238, "subsections": 56, "sections": 11,
  "years": {"2026": 908, "2025": 417, "...": 0},
  "per_section": {"s2": 213, "...": 0},
  "stream_items": 231, "stream_updated": "2026-10-17T00:00:00Z",
  "stream_polarity": {"good": 93, "bad": 97, "mixed": 41},
  "stream_per_source": {"manipulation": 71, "misalignment": 47, "mistakes": 40},
  "stream_per_op": {"constrain": 149, "deploy": 85, "...": 0},
  "stream_per_sub": {"s1_1": 3, "...": 0}
}
```

`source_generated` is `corpus_full.json.generated`, the date of the paper data the build read.
`cited` counts distinct cited documents (selected papers plus selected grey records after the merges
above). `zh` counts cards with `has_zh`. The `stream_*` counts are derived from `stream.json` by
`build_data.stream_derivatives()` and rewritten by the collector on every run; the landing page reads
them instead of `stream.json`.

## `stream_recent.json`

`{"generated": "<stream.json generated>", "items": [...]}`: the twelve newest items of `stream.json`,
same item schema, newest first. Written by `build_data.py` and by the collector. The landing page
reads this file and falls back to `stream.json` when it is absent.

## `stream.json`  (the live stream)

```json
{
  "generated": "2026-10-17T12:00:00Z",
  "taxonomy_generated": "2026-10-17",
  "sources": ["seed sweep 2026-10-17", "collector"],
  "items": [
    {
      "id": "2025-07-18-replit-agent-deleted-production-database",
      "date": "2025-07-18",
      "date_precision": "day",
      "title": "Replit's coding agent deleted a production database during a code freeze",
      "url": "https://...",
      "also_urls": ["https://..."],
      "publisher": "Fortune",
      "kind": "incident",
      "polarity": "bad",
      "summary": "Two factual sentences taken from the source, no speculation.",
      "failure_sources": ["mistakes"],
      "requirements": ["in-scope", "correct"],
      "operations": ["constrain", "intervene"],
      "subsections": ["s2_1", "s4_1", "s6_5"],
      "domain": "coding",
      "actors": {"vendor": "Replit", "deployer": "SaaStr", "model": null},
      "evidence": "first-party",
      "related_papers": ["khan2026token", "rahman2026locating"],
      "tags": ["destructive action", "rollback"],
      "verified": true,
      "verified_on": "2026-10-17",
      "verification_note": "URL fetched; date and claims confirmed from the article body.",
      "added_by": "seed-sweep",
      "lens": "incidents-coding"
    }
  ]
}
```

Enumerations:

- `kind`: `incident` (harm occurred), `near-miss` (caught before harm), `deployment` (an agent put
  into real use, with or without reported controls), `safety-feature` (a vendor or deployer shipped a
  control mechanism), `evaluation` (a published test of deployed or deployable agents, including system
  cards and red-team reports), `research` (a paper or report with direct deployment relevance),
  `policy` (law, regulation, standard, enforcement, lawsuit), `disclosure` (vendor postmortem or security
  advisory).
- `polarity`: `bad` (a failure or harm), `good` (a success or a control that worked or shipped), `mixed`.
- `failure_sources`: subset of `mistakes | manipulation | misalignment`; empty for items that are not
  about a failure.
- `requirements`: subset of `correct | compliant | in-scope | within-budget | safe`.
- `operations`: subset of `constrain | observe | intervene | steer | train | verify | deploy`; the
  operation that failed, was missing, or worked.
- `subsections`: 1 to 4 subsection ids from `taxonomy.json`, most specific first.
- `domain`: free text from a small controlled list: `coding`, `browsing`, `customer-service`,
  `finance`, `email-and-office`, `healthcare`, `legal`, `cyber`, `research`, `infrastructure`,
  `consumer`, `government`, `multi-agent`, `other`.
- `evidence`: `first-party` (the vendor or deployer said so), `press`, `researcher`, `regulator`,
  `court`, `incident-database`.
- `date_precision`: `day | month | year`.
- `also_urls` (optional): further URLs that report the same event. One item per event: the most
  primary source is kept as `url` (vendor disclosure or official report > researcher > incident
  database > press), the others go here, and `related_papers` and `tags` are the union across the
  reports. Absent when the event has a single source; never empty. Dedupe must consider these URLs too.

`taxonomy_generated` is the `generated` date of the `taxonomy.json` the items were classified against.
Subsection ids are positional, so a renamed or reordered outline changes their meaning; the collector
warns and `pipeline/tests/test_collector.py` fails when it differs from the current `taxonomy.json`,
and items must then be re-filed (as the nine reward-hacking items were moved from `s2_3` to `s2_4` on
2026-10-17).

Every item must have a working `url`, a `date`, and `verified: true` with a note; unverifiable items
are not published. `id` = `YYYY-MM-DD-` + slug of the title (ASCII, hyphens, max 80 chars), as produced
by `make_id()` in `pipeline/collect_news.py`. `date` is the event date when the source states it,
otherwise the publication date. Items are sorted by `date` descending in the file.
